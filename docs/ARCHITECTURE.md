# Architecture

React 19.3, TypeScript 6.0.3, Vite 8.3, Zod 4.6.5, idb 8.0.3, safe react-markdown 10.1, and Node 24.19.0. Exact versions and transitive resolution live in the lockfile. This was a verified empty repository, so no legitimate application architecture was replaced. TypeScript 7 was not selected because the inspected lint dependency peer range ended at TypeScript 6.

The build discovers every directory under `content/courses/` and loads its `course.json`, ordered lesson JSON, and Markdown sections. It also discovers `content/paths/*.json` and resolves canonical references against the complete catalog. Runtime catalog/path/search JSON is generated; no course registry or course-specific route exists. `src/content-schema.ts` validates structure and references; `scripts/content.ts` also checks actual asset/download files and pinned design hashes. Fixtures are outside production content. Package contracts enforce coverage minima, while the launch preservation manifest protects every original ID without imposing an exact 12×3 ceiling on additions. Unrelated packages do not inherit this manifest.

Hash navigation addresses global IDs (`#/lesson/<lesson-id>/<section-id>`, `#/course/<course-id>`, `#/practice/<scenario-id>`). A `?path=<path-id>` query supplies explicit path context, with optional bridges and ordered canonical topic IDs. Direct topics retain an explicit course fallback. Display titles, filenames and array order never own study data. Vite's base controls assets and downloads. Root and `/SpicyBrain/` builds are browser-tested using a plain static server, without fallback rewrites. Links to removed content explain the situation; notes/drafts remain editable and exportable.

Rendering uses a small Markdown element whitelist, no raw HTML/MDX/code execution, and no arbitrary runner. SVG teaching assets are original schematics with title, description, caption, alt text and a text equivalent. Native modal dialogs support zoom, reset, Escape and focus return. Build validators reject unsafe schemes, traversal, scripts and external SVG references. Imported personal text is rendered through text controls, never interpreted as HTML.

The single IndexedDB root record makes event+schedule and replace/import atomic. Record families are separate inside the validated snapshot. Optimistic edits retain text in memory; serialized read/write transactions replay pending operations against the latest persisted record to prevent ordinary multi-tab updates from overwriting unrelated changes. This is a local learning application, not a multiuser collaboration system. Two simultaneous edits to the same note are not a live conflict editor; explicit backup merge preserves divergent text.

The catalog is two-tier. The initial bundle carries only the catalog tier (`src/catalog-types.ts`): every identity, title, mapping, count, rubric, source/claim/concept record and asset description the interface needs to navigate, count due cards and schedule, but no section Markdown, card or question text, scenario body, lab/guide/case body or extension-card text. Card and question entries are references (`id`, `revision`, plus lesson/section for cards); the compact teaching index likewise lists extension cards by reference and only the check identities study records can cite. The body tier is one same-origin JSON file per lesson, scenario, lab, guide and case under `public/teaching/bodies/<id>.json`, fetched on demand by `src/bodies.ts`, validated with Zod and identity-checked against the catalog (id, kind, lesson `contentVersion`, section set, card and question revisions) before it is cached; a failed load is evicted so Retry fetches again, and every view keeps notes, drafts, bookmarks, positions and navigation working from the catalog tier while a body loads or after it fails. Complete teaching bodies are bounded per-module JSON (750,000-byte maximum) loaded on demand the same way, with the module's own extension-card text; a module workspace loads the module and the lesson bodies its beats and cards draw on in parallel, and a review session resolves card text through those same files. Course-wide handbook assembly deliberately loads all modules only when requested. Search and the media register are separate lazy same-origin files; all course, beat, extension and concept entries remain searchable without a server. `scripts/measure-bundle.mjs` prints the resulting sizes and `docs/academy/SCALE.md` records them. The build still reports its existing >500 KB uncompressed-chunk advisory. Optional exercise archives remain separate hash-validated static downloads; the app never executes them.

`content/teaching/<course>/` contains generic module specifications validated by `src/teaching-schema.ts`: ordered stable beats, shared concept/source/claim/question/visual references, staged node/table/equation visuals, handbook depth, optional Samajh, preserved card mappings and researched extension cards. Module counts and titles are content choices. The engine has no Databricks/photography branch. A beat links a precise canonical lesson/section without duplicating its historic completion. Markdown accepts explicit concept tokens outside code and safe links; raw HTML, arbitrary images/scripts and invalid references are rejected. Hover, focus and touch definitions use measured, dismissible popovers.

The CSP keeps script/font/connect resources same-origin, required inline styles, and disabled object embedding. Its only frame provider is `https://www.youtube-nocookie.com`. A curated player URL is strictly allowlisted and instantiated only after the learner chooses **Load video player**. No remote thumbnail or provider request precedes that choice. The frame gets a scoped origin referrer (required by the provider), never the hash route or note/search text. Provider resources can contact Google/YouTube after consent: privacy-enhanced embedding is not zero tracking. External original links and an authored illustrated equivalent remain available. No watched/completion evidence is inferred. Remote fonts in the app remain removed. No service worker, analytics, model API, cloud sync, backend, code runner, deployment workflow, or cross-origin personal search exists.

`src/` is the reusable engine; `content/` is the production teaching package; `scripts/` builds/reports/tests extensions; `tests/fixtures/` contains synthetic migration and photography inputs; `docs/evidence/` contains public-safe builder evidence. The content-only extension test copies the project into a temporary isolated directory, adds only content inputs, builds and drives the real production browser, renames/reorders content, verifies state, exercises revisions, removes the fixture, and checks release cleanup plus unchanged engine hashes.
